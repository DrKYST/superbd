# Отличия клиента от макета

Заполняется при разработке клиента (правило 4 в `docs/ui/ui-spec.md`). Пустая таблица = клиент совпадает с макетом.

| Экран | В макете | Сделано в клиенте | Причина | Согласовано со студентом |
|---|---|---|---|---|
| Все окна | Заголовок окна: «СуперБД: Учёт услуг…» чёрным, «(ФИО, роль, провайдер)» серым | Весь заголовок одним цветом | Заголовок рисует Windows, раскрасить части текста средствами Qt нельзя | нет |
| Все окна | Крестик «×» на вкладке, в том числе на «Начальной странице» | Стандартная кнопка закрытия вкладки Qt; у «Начальной страницы» её нет | «Начальная страница» по ui-spec §3 всегда открыта, закрыть её нельзя | нет |
| Начальная страница | «По вопросам доступа обращайтесь к администратору системы: Шевченко Ирина Олеговна, доб. 101.» | ФИО администраторов из базы (`api.whoami().admin_contact`), без добавочного номера | В макете — образец; телефонов сотрудников в модели данных нет | нет |
| Начальная страница оператора | «В списках видны только абоненты, у которых есть договор с вашим провайдером, и абоненты, созданные вами.» | Текст макета без изменений | По D25 (общий реестр) первая часть фразы верна; «созданные вами» лишнее — абонент создаётся только вместе с договором. Поправить в макете (предложено: «В списках видны только абоненты, у которых есть договор с вашим провайдером.») | ожидает решения |
| Панель навигации | У разделов «Мой провайдер», «Провайдеры» (главный аналитик), «Сеансы связи» (руководитель, аналитик) навигация не нарисована (ссылки `#`) | «Мой провайдер» → «Карточка провайдера»; «Провайдеры» → «Провайдеры»; «Сеансы связи» для ролей просмотра → «Журнал сеансов», «См. также: Абоненты» | Минимальный состав по образцу нарисованных разделов | нет |
| Панель разделов администратора | «Администри­рование» с мягким переносом | «Администри-» / «рование» — перенос задан явно | `QToolButton` не переносит текст сам | нет |
| Администратор БД (все экраны) | Роли нет (D26) | Разделы «Главное · Администрирование · База данных»; навигация по образцу администратора: «Пользователи», «Журнал изменений», «Таблицы», «Подключения»; тексты начальной страницы — по образцу администратора приложения; «Журнал изменений», «Таблицы», «Подключения» — заглушки до артбордов макета | Новая роль (D26) | да, 07.10 (концепция) |
| Навигация администратора приложения | «Администрирование» → «Пользователи», «Журнал изменений» | Только «Пользователи» | Журнал изменений перешёл к администратору БД (D26) | да, 07.10 |
| Начальная страница администратора приложения | Роль «администратор»; счётчик «Изменений в журнале за сегодня»; тексты `R.admin` | Роль «Администратор приложения»; вместо счётчика журнала — «Пользователей системы»; в описании — «учётные записи операторов, руководителей и главных аналитиков», в «Недоступно» — «журнал изменений и обслуживание базы данных», в «Справке» — «Администраторов приложения создаёт администратор БД» | Разделение администраторов (D26) | да, 07.10 |
| Запросы | Экран-витрина «Запросы» (Queries.png), раздел «Запросы» у руководителя и главного аналитика, ссылки «Запросы» / «24 готовых запроса к базе» / «готовые запросы с параметрами» на начальной странице и в навигации «Статистики» | Экрана и раздела нет; запросы работают в основных модулях | Решение студента (D23): витрина не нужна, запросы используются на рабочих экранах; макет обновить при следующей правке холста | да, 30.09 |

| Карточки абонента и договора, «Мой провайдер» | Нарисована только форма «Договор (создание)» | Карточка договора — та же форма в режиме просмотра (кнопки записи недоступны, вкладка «Сеансы» с итогами); карточка абонента и «Мой провайдер» — простые формы просмотра | Создание и изменение — этап CRUD | нет |
