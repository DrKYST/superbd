# Лабораторные работы: задания и требования к отчётам

Источник: «Методические указания к выполнению лабораторных работ по дисциплине „Программирование систем с серверами баз данных“», ДонНТУ, 2024 (Щедрин С. В., Бердюкова С. С., Филипишин Д. А.). PDF в `docs/source/` с повреждённым текстовым слоем — пользоваться этой расшифровкой.

## Общий порядок (из методички)

- После оформления ТЗ на курсовую студент настраивает свой сервер БД, затем проектирует таблицы, интерфейс, SQL-запросы.
- На занятии студент предъявляет выполненное задание, поясняет и обосновывает решение.
- **К следующей лабораторной оформляется отчёт по выполненной**, предварительно защищённый у преподавателя.
- **Подписанные отчёты — основная часть курсовой работы**; затем они дорабатываются до рабочего макета, максимально приближенного к законченному программному продукту.

Общая шапка любого отчёта: 1) титульный лист, 2) тема, 3) задание. Далее — пункты, указанные у каждой лабы.
По договорённости со студентом отчёты оформляются **только по лабораторным № 1 и № 7** (D16). По остальным — только выполнение, защита и перенос результата в курсовую.

## ЛР 1. Установка и настройка сервера

Цель: настройка и повышение производительности сервера на примере PostgreSQL.

Задание: установить PostgreSQL и произвести начальную настройку (файл `postgresql.conf` в каталоге `data`):
- `shared_buffers` — исходя из конфигурации компьютера и ОС (на выделенном сервере ≈ 1/4 ОЗУ; на Windows эффективнее 64–512 МБ);
- `work_mem` — исходя из конфигурации (стартово 2–4 % доступной памяти; при 1–4 ГБ ОЗУ — 32–128 МБ);
- `temp_buffers` — порядка 16–32 МБ;
- `max_prepared_transactions` — можно оставить 5;
- `max_files_per_process` — уменьшать при ошибке «Too many open files»;
- `track_counts = on`.
Также в методичке описаны `max_connections`, `huge_pages` (off/on/try), `max_stack_depth` (2–4 МБ), `default_statistics_target`, `effective_cache_size` (≈ 2/3 ОЗУ на выделенном сервере), `random_page_cost` (снижать до 1.5–3 на быстрых дисках), `track_functions`, `track_activities`.

Отчёт: титульный лист; тема; задание; скриншоты выполненных требований; пояснения заданных значений для используемого сервера.

Использование в курсовой: раздел 2 ПЗ («Обоснование выбора СУБД, описание возможностей СУБД»).

## ЛР 2. Проектирование концептуальной модели базы данных

Цель: изучение представления данных об объектах предметной области и их связях в рамках реляционной модели.

Методическая часть: реляционная модель (Кодд), отношение/кортеж/атрибут/домен, первичный ключ (естественный, составной, искусственный: числовой, символьный, счётчик), внешний ключ, ссылочная целостность, связи 1:1, 1:N, M:N (через таблицу пересечения), нормализация до 3НФ, аномалии обновления/включения/удаления. Разобраны примеры «Продукция молокозаводов» и «Посредническая фирма».

Задание: для предметной области своего варианта курсового проекта выделить объекты и представить их взаимосвязанными таблицами в **3НФ**. Определить **базовые таблицы и таблицы-справочники**; указать **первичные и внешние ключи**. **Описать типы полей.**

Отчёт:
1. Титульный лист.
2. Тема.
3. Задание.
4. Концептуальная модель БД по варианту.
5. Первичные и внешние ключи.
6. Типы полей в основных таблицах и таблицах пересечения.

Контрольные вопросы (к защите):
1. Определения: предметная область, БД, СУБД; реляционная модель данных; нормализованная таблица, нормализация; 1НФ, 2НФ, 3НФ; первичный, искусственный, внешний ключ; целостность данных, ссылочная целостность.
2. Виды связей между объектами предметной области.

Рекомендуемое оформление модели — методика IDEF1X по пособию Ильиных/Шустовой: пул сущностей, матрица связей, таблица описания связей, таблица доменов, таблица атрибутов, даталогические таблицы (имя колонки, домен, тип, обязательность, ключи, правило удаления).

Использование в курсовой: ТЗ п. 1, разделы 1 и 4.1 ПЗ.

## ЛР 3. Создание базы данных

Цель: освоение создания таблиц и установления связей между ними.

Порядок: 1) создать таблицы, свойства полей и таблиц, подстановки для внешних ключей — **сначала главные таблицы (сторона «один»), затем подчинённые**; 2) установить связи, создать схему данных; 3) заполнить таблицы данными.

Задание: для спроектированной модели в выбранной СУБД определить таблицы, указать типы и свойства полей (основные свойства, подстановка), создать схему данных.

Отчёт:
1. Титульный лист.
2. Тема.
3. Задание.
4. Скриншот созданной схемы данных с указанными типами связей.
5. 2–3 скриншота основных таблиц в режиме конструктора.
6. 2–3 скриншота справочных таблиц в режиме конструктора.

Использование в курсовой: ТЗ п. 2 и 4, раздел 4.2 ПЗ, приложение Б.

## ЛР 4. Проектирование интерфейса клиентской части курсового проекта

Цель: спроектировать интерфейс клиентской части курсового проекта.

Методическая часть: пример разобран на предметной области «абонент / договор / фирма-провайдер / тариф / доп. услуги (IPTV, тип IP-адреса, скидки)». Роли примера: Оператор_1 (добавляет абонентов и договоры), Оператор_2 (добавляет фирмы-провайдеры), Администратор (справочники, создание операторов и назначение им ролей).

**Внимание:** пример методички почти совпадает с нашим вариантом Б-16. Копировать его макеты, названия и набор ролей нельзя — преподаватель узнает пример. Наша система отличается (см. `docs/analysis/requirements.md`): роли привязаны к провайдеру, есть сеансы связи и статистика.

Задание: в **любой программе** спроектировать интерфейс клиентской части курсового проекта для нескольких ролей (**не менее 3-х**). Согласовать проект интерфейса с преподавателем.

Отчёт: титульный лист; тема; задание; скриншоты спроектированного интерфейса.

Рекомендация: проектировать сразу в Qt Designer (`.ui`-файлы в `client/src/ui/`) — эти формы потом станут настоящими формами клиента.

Использование в курсовой: раздел 3 (3.2 визуальные компоненты), раздел 5, приложение Г.

## ЛР 5. Разработка простых запросов на выборку

Задание:
1. Сформулировать запросы:
   - симметричное внутреннее соединение с условием (два — с отбором по внешнему ключу, два — по датам);
   - симметричное внутреннее соединение без условия (три запроса);
   - левое внешнее соединение;
   - правое внешнее соединение;
   - запрос на запросе по принципу левого соединения.
   Запросы должны использовать данные **из нескольких таблиц**, условия отбора задаются **через параметры**.
2. Создать эти запросы.
3. Дополнить таблицы записями, согласующимися с запросами.

Отчёт: титульный лист; тема; задание; формулировки запросов; код каждого запроса; скриншоты результатов.

Использование в курсовой: ТЗ п. 5–6, разделы 4.7, 4.8 ПЗ.

## ЛР 6. Разработка сложных запросов на выборку

Задание:
1. Сформулировать запросы:
   - итоговый запрос без условия;
   - итоговый запрос с условием на данные;
   - итоговый запрос с условием на группы;
   - итоговый запрос с условием на данные и на группы;
   - запрос на запросе по принципу итогового запроса;
   - запрос с подзапросом.
   Данные из нескольких таблиц, условия — через параметры.
2. Создать запросы.
3. При необходимости дополнить таблицы записями.

Отчёт: как в ЛР 5.

Замечание: курсовой нужен более широкий набор (итоговый «всего / в том числе», условие на данные по значению / маске / с индексом / без индекса, UNION, подзапросы с IN / NOT IN / CASE / над итогами). Выгодно сделать их все уже в ЛР 6.

Использование в курсовой: ТЗ п. 5–6, разделы 4.7, 4.8, 5.4 ПЗ.

## ЛР 7. Практическое применение документно-ориентированных баз данных

Цель: подходы построения и моделирования документно-ориентированных БД с помощью JSON/JSONB в PostgreSQL (принципы NoSQL).

Методическая часть: пример опять на предметной области «абонент/договор/фирма» (ключи `name`, `type_abonent`, `dogovor[]`, `firma{}`, `tarif`, `dop_usluga`) — **не копировать структуру и имена ключей**. Показаны операторы `->`, `->>`, `#>>`, `@>`, `@@`, jsonpath, `jsonb_array_elements`, `jsonb_path_query(_array)`, `jsonb_populate_record(set)`, `jsonb_each_text`, `jsonb_set`, `jsonb_insert`, `||`, `-`, GIN-индексы, EXPLAIN ANALYZE до/после.

Требования:
- придумать и написать пример структуры JSON по заданию;
- создать таблицу для хранения JSON;
- заполнить **не менее 100 000** псевдоданных, **глубина вложенности не менее 4**;
- запросы с выводом конкретных полей/объектов/массивов с одним или несколькими условиями — **не менее 3**;
- запросы с jsonpath — **не менее 3**;
- запросы с функциями обработки JSON — **не менее 3**;
- обновление/добавление/удаление данных внутри документа — **не менее 6**;
- удаление документов — **не менее 2**;
- индексы — **не менее 3** (1 по полю с документом целиком, не менее 2 по элементам ключей);
- анализ запросов EXPLAIN (ANALYZE);
- оптимизировать **не менее 5 запросов**, чтобы они использовали индексы и стоимость узлов плана не выросла.

Отчёт: титульный лист; тема; задание; пример структуры JSON; примеры запросов; код создания индексов; анализ и оптимизация запросов.

Использование в курсовой: раздел 2 ПЗ (возможности СУБД); журнал аудита `audit.change_log` с `jsonb` (см. `docs/decisions.md`).

## ЛР 8. Секционирование баз данных (партицирование)

Цель: построение секционированных таблиц и БД на их основе в PostgreSQL.

Методическая часть: `PARTITION BY RANGE / LIST / HASH`, секции `PARTITION OF … FOR VALUES …`, `DEFAULT`, индекс на секционированной таблице, `ATTACH / DETACH PARTITION`, `CREATE TABLE … (LIKE … INCLUDING DEFAULTS INCLUDING CONSTRAINTS)` + `CHECK` перед присоединением, вложенные секции, сравнение с обычной таблицей через EXPLAIN (ANALYZE).

Задание (**вариант 16**):
- создать секционированную таблицу — **партиция № 1: по диапазону**; **не менее 4 секций + секция по умолчанию**; заполнить **не менее 500 000** записей;
- создать ещё одну секционированную таблицу — **партиция № 2: по списку**; не менее 4 секций + default; скопировать данные из партиции № 1;
- создать простую таблицу — копию секционированной; скопировать данные из партиции № 1;
- создать индексы (один по ключу разбиения и несколько по ключевым полям) на секционированных и обычной таблицах;
- **дополнительно: создание вложенных секций в партиции № 1**;
- сравнение и анализ партиций и обычной таблицы (EXPLAIN ANALYZE).

Отчёт: титульный лист; тема; задание; создание секционированных таблиц; создание секций; код создания индексов; добавление/удаление данных из секционированных таблиц; сравнение и анализ партиций и обычной таблицы.

Использование в курсовой: ТЗ п. 8, раздел 4.6 ПЗ (секционирование `core.session`).
