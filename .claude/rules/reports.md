# Правила для текстов отчётов и пояснительной записки

- Исходник — Markdown в синтаксисе `tools/md2docx/README.md`; .docx только генерируется, вручную не редактируется Claude.
- Стиль — научно-технический, безличный («разработана», «выполнено»), без «мы/я», без эмодзи, без markdown-украшений вне поддерживаемого синтаксиса.
- Отчёт по лабе содержит ровно пункты «Отчёт» для этой лабы из `docs/task/labs.md`, в том же порядке, плюс короткие выводы. Шапка: тема, цель, задание.
- Каждый рисунок, таблица и листинг — с подписью и меткой `{#…}`, и на каждый есть ссылка `[@…]` в тексте **до** объекта.
- Скриншоты: файлы в `labs/labNN/screenshots/` с говорящими именами (`schema.png`, `table_contract_design.png`). Если скриншота нет — всё равно ставить ссылку на ожидаемое имя: генератор вставит заглушку, а студент увидит, что снять. Список ожидаемых скриншотов — в `labs/labNN/README.md`.
- Код в отчёте — фрагменты из реальных файлов `db/`/`client/`, не переписанные по памяти; длинные листинги — в приложение ПЗ, в отчёт — ключевые части.
- Таблицы полей (типы, ключи) генерировать из фактической схемы (`COMMENT ON`, `information_schema`), а не вручную.
- Не копировать формулировки и примеры методички (особенно примеры ЛР 4 и 7 на похожей предметной области).
- Рисунки/таблицы/листинги в ПЗ нумеруются сквозной нумерацией; в приложениях — с буквой («А.1»).
