## Стиль

Классический десктоп-клиент учётной системы, по образцу 1С:Предприятие 8.3 («Такси») и Swing-клиентов биллингов (BGBilling, UTM5): панель разделов сверху, панель навигации раздела слева, вкладки открытых окон, командная панель с жёлтой кнопкой по умолчанию («Создать», «Записать и закрыть»), таблицы с сеткой и жёлтой текущей строкой, группы полей «Отбор», формы элементов «(создание)», строка состояния. Шрифт Arial, квадратные поля ввода с кнопками выбора «…». Такой вид напрямую реализуется в Qt Widgets (QTableView, QToolBar/QToolButton, QTabBar, QGroupBox).

## На что ориентировались

| Система | Что взято |
|---|---|
| 1С:Предприятие 8.3 | панель разделов и панель навигации, вкладки открытых окон, командная панель («Создать», «Найти…», «Еще»), «Записать и закрыть», жёлтая текущая строка, группа «Отбор», формы «(создание)», отчёт как табличный документ с диаграммой |
| BGBilling, Hydra | договор как центральный объект, карточка договора с вкладками, связка «абонент → договоры → сеансы» |
| UTM5, LANBilling | дерево групп пользователей, тарифы с временными диапазонами (сетка «день × час») |
| RADIUS (accounting), NetFlow | состав журнала сеансов: начало, IP-адрес (Framed-IP), объём, тариф, стоимость; итоги трафика |
| Salesforce | связанные списки под основным (договоры и сеансы под абонентом) |

С примером методички (Оператор_1 / Оператор_2 / Администратор, IPTV) не совпадает: другие роли, состав экранов, есть сеансы, отчёты и запросы.

## Соответствие требованиям к интерфейсу

- не менее 3 ролей — 4 (оператор, руководитель, главный аналитик, администратор);
- одна страница на тему, инструменты по роли — «Абоненты и договоры» (оператор/руководитель), «Статистика» (руководитель/главный аналитик) — один и тот же экран;
- исключительная тематика одной роли — «Пользователи», «Справочники» у администратора;
- пагинация 20/100/200, «страница X из Y»;
- составная форма «один-ко-многим»: абонент → договоры → сеансы;
- начальник: фильтры, распределение по временным отрезкам, диаграмма, экспорт в Excel; «председатель» (главный аналитик) видит сводку по всем провайдерам;
- ID на экране нет.

## Для разработки клиента (Qt)

Макет для Claude Code переложен в `docs/ui/`: спецификация `ui-spec.md` (обязательные правила, экраны → классы Qt, каркас, элементы, стиль, чек-лист), картинки всех 17 экранов `screens/`, исходники `mockup/`, таблица стилей Qt `superbd.qss`. Клиент делается строго по нему.


Каждому экрану — страница `QWidget` в `QStackedWidget` главного окна; левая панель — `QListWidget`/`QToolButton` по списку разделов роли из `api.whoami()`; списки — `QTableView` + модель с ID в `Qt::UserRole`; диаграммы — Qt Charts; Excel — QXlsx. Диалог договора — `QDialog`.

## Вопросы к защите

- Почему руководитель не получает отдельную страницу «Абоненты»? — методичка запрещает дублировать страницы одной тематики по ролям; экран один, кнопки скрываются, а запрет изменений обеспечивает БД.
- Где проверяется роль? — в PostgreSQL (группы, функции `api`, RLS); клиент лишь не показывает недоступные разделы.
- Почему стоимость сеанса в форме «предварительная»? — окончательно её вычисляет сервер (триггер), клиент ничего не считает.
