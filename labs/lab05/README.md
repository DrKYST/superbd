## Вопросы к защите

**Внутреннее соединение** — в результат попадают только строки, для которых нашлась пара во всех соединяемых таблицах (журнал сеансов: сеанс ⋈ договор ⋈ абонент ⋈ тариф). **Симметричное** — порядок таблиц не влияет на результат.

**Условие по внешнему ключу / по датам** — отбор задаётся параметром функции: `s.contract_id = p_contract_id` (№ 2), `s.started_at >= p_from AND s.started_at < p_to + 1` (№ 3; `+ 1` — чтобы включить весь последний день).

**Левое внешнее соединение** (№ 8) — все строки левой таблицы (абоненты), даже если справа пары нет; у абонента без договоров колонки договора — NULL, `count(c.id)` = 0. Абонентов без договоров видит главный аналитик (реестр общий, D25); оператору абонент виден, пока у его провайдера есть с ним договор, а в счётчиках — только договоры своего провайдера.

**Правое внешнее соединение** (№ 9) — все строки правой таблицы (тарифы), даже без сеансов за период: руководитель видит, что тарифы «Праздничный» и «Служебный» не использовались.

**Запрос на запросе** (№ 10) — источником служит другой запрос: представление `v_providers` соединяется слева с подзапросом, считающим договоры по провайдерам; провайдер без договоров остаётся в списке с нулём.

**Почему запросы без условия — представления, а с условием — функции** — требование ТЗ п. 6; к тому же у представления нет параметров, а функции принимают отбор, страницу и возвращают `total_count`.

**Почему функции `SECURITY DEFINER`** — у групп пользователей нет прав на таблицы `core`/`ref`; функция выполняется от имени владельца, но первой строкой проверяет группу вызывающего (`session_user`), а строки ограничивает его провайдером.

**Как сделаны итоги «Итого…»** — оконные функции `count(*) OVER ()`, `sum(cost) OVER ()` считаются по всему отбору до `LIMIT`, поэтому на любой странице итог — за весь период, а клиент ничего не суммирует.

**Зачем `sec.like_prefix`** — пользователь может ввести `%` или `_`; без экранирования поиск «%» выбрал бы всех. Шаблон «начинается с» позволяет использовать индекс `(lower(name) text_pattern_ops, цифры телефона)` — тот же уникальный индекс, что не допускает дублей в реестре (D25).

**Что показывают планы** — `explain/q08.txt`: абоненты оператора — `Hash Semi Join` с договорами его провайдера (договоры по индексу провайдера), затем левое соединение с договорами (`Nested Loop Left Join`); `q06.txt`: ветвь главного аналитика не выполняется (`never executed`); `q03.txt`: отбор сеансов за период по индексу `ix_session_started_at`; `q09.txt`: `Hash Right Join` сеансов периода с тарифами.
