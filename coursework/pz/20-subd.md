# 2 Обоснование выбора СУБД, описание возможностей СУБД

<!-- Источники: docs/server-config.md (ЛР 1), labs/lab07/README.md (ЛР 7), docs/decisions.md (D6, D19, D24, D26, D27, D30). -->

В качестве сервера баз данных выбрана СУБД PostgreSQL 18 — свободно распространяемая объектно-реляционная СУБД с открытым исходным кодом [3]. Выбор определён требованиями к системе (вся логика программного обеспечения — на сервере, роли пользователей — средствами СУБД, защита на уровне строк, секционирование) и возможностями, которые PostgreSQL предоставляет для их выполнения:

- роли и группы ролей: пользователь системы — роль с правом входа, член группы; права на схемы, таблицы и функции выдаются группам командами GRANT и REVOKE; пароли хранятся в системном каталоге в виде хеша SCRAM-SHA-256;
- функции на SQL и PL/pgSQL, выполняемые с правами владельца (SECURITY DEFINER) и с заданными параметрами сеанса (search_path, часовой пояс), — через них пользователи получают доступ к данным, не имея прав на таблицы;
- политики защиты на уровне строк (ROW LEVEL SECURITY), действующие и на владельца таблицы при включённом режиме FORCE;
- декларативное секционирование таблиц по диапазону, списку и хешу, в том числе многоуровневое;
- домены, проверочные ограничения, внешние ключи с выбором правила удаления, столбцы идентификаторов (GENERATED AS IDENTITY) и последовательности;
- типы данных предметной области: numeric для денежных сумм без ошибок двоичного округления, inet для IP-адресов и подсетей, timestamptz для моментов времени, jsonb для слабоструктурированных документов;
- оконные функции, группировка с ROLLUP, общие табличные выражения, частичные индексы и индексы по выражениям, пропуск по первой колонке составного индекса (Skip Scan, появился в версии 18);
- инструменты анализа плана выполнения запросов (EXPLAIN ANALYZE, модуль auto_explain) и сбора статистики.

Сервер установлен на компьютере разработчика под управлением Windows 11 (служба postgresql-x64-18, порт 5432). Параметры, влияющие на использование памяти и ресурсов, изменены командой ALTER SYSTEM (запись в файл postgresql.auto.conf) с последующим перезапуском службы; значения приведены в таблице [@tab:server-config].

Так как функции смены и сброса пароля передают новый пароль серверу параметром запроса, для журнала сервера установлено log_parameter_max_length = 0: значения параметров не записываются в журнал ни для медленных, ни для ошибочных запросов. Пароли администраторов базы данных меняются командой \password программы psql, которая отправляет на сервер уже вычисленный хеш.

Кроме реляционных таблиц PostgreSQL хранит слабоструктурированные данные в типе jsonb — двоичном представлении документа JSON с индексируемым доступом к ключам. В предметной области такие данные — учётные записи сеансов, которые биллинг провайдера выгружает по каждому сеансу: набор атрибутов зависит от производителя оборудования доступа и меняется со сменой оборудования, поэтому запись хранится целиком, а нужные поля извлекаются запросами. Для работы с документами СУБД предоставляет операторы извлечения значения по ключу и пути, проверки вхождения образца и наличия ключей, язык путей SQL/JSON (jsonpath), функции разбора документа в строки таблицы и сборки документа из строк, изменения части документа. Поиск ускоряют обратные индексы GIN по документу целиком и индексы B-дерева по выражению над отдельным ключом. На 100 025 учётных записях, построенных из данных системы в лабораторной работе № 7, индексы сократили время типовых запросов с десятков миллисекунд до долей миллисекунды. В самой системе тип jsonb предназначен для журнала изменений audit.change_log: строка до и после изменения хранится документом, поэтому журнал не зависит от структуры таблиц.

Секционирование позволяет хранить большую таблицу частями (секциями) по значению ключа: запросы за период читают только нужные секции, а устаревшие данные отсоединяются целиком. Для системы кандидатом является таблица сеансов связи — единственная неограниченно растущая таблица; её первичный ключ уже включает дату сеанса, как того требует секционирование по дате. Применение секционирования описывается в подразделе 4.6.

Для администрирования используется pgAdmin 4 (просмотр объектов, построение схемы данных, выполнение запросов) и программа psql (сценарии создания и пересборки базы, автоматические тесты).
