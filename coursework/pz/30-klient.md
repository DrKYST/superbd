# 3 Обоснование выбора инструментальных средств для написания клиентской части, проектирование структуры ПО

<!-- Источники: client/README.md, client/CMakeLists.txt, client/src, docs/ui/ui-spec.md, docs/decisions.md (D18, D22). Снимки — coursework/pz/img (client/build-dev/claude_pz_shots.cmd). -->

Клиентское приложение разработано на языке C++17 с библиотекой Qt 6 (модули Widgets, Sql, Charts, PrintSupport, Svg) и системой сборки CMake [7]. Выбор обусловлен следующим:

- модуль Qt Sql содержит драйвер QPSQL, работающий через клиентскую библиотеку PostgreSQL libpq, и позволяет выполнять подготовленные запросы с привязкой параметров (prepare и bindValue), что исключает внедрение SQL-кода через пользовательский ввод;
- архитектура «модель — представление» Qt (QAbstractTableModel, QTableView) отделяет загрузку данных от их отображения, что позволяет вынести постраничную загрузку из функций сервера в один общий класс модели;
- Qt Charts строит диаграммы отчётов, модуль PrintSupport печатает их, а библиотека QXlsx [8] сохраняет отчёты в формате Excel без установленного Microsoft Office;
- формы проектируются в Qt Designer, а оформление задаётся таблицей стилей Qt (QSS) — единый стиль всех экранов по согласованному макету интерфейса;
- приложение компилируется в исполняемый файл Windows без среды выполнения, для запуска достаточно библиотек Qt и libpq рядом с программой.

Приложение — тонкий клиент: оно подключается к PostgreSQL под учётной записью пользователя, вызывает функции и представления схемы api и отображает результат. SQL-текст в клиенте формируется только вида «SELECT * FROM api.<функция>(<параметр> => :<параметр>, …)» с проверкой имени объекта; значения передаются параметрами. Пароль не сохраняется: в файле config.ini рядом с программой хранятся только адрес сервера, порт, имя базы и последний логин. Структура исходного кода приведена в таблице [@tab:client-structure].

## 3.1 Невизуальные компоненты для работы с данными

Класс Db создаёт единственное подключение QPSQL под логином и паролем пользователя, после подключения вызывает функцию api.whoami и заполняет структуру Whoami (логин, ФИО, группа, название роли, провайдер, версия сервера); по ней строится весь интерфейс. Метод Db::userMessage извлекает из ошибки сервера текст сообщения RAISE EXCEPTION без служебных префиксов драйвера — пользователь видит, например, «Недостаточно прав для этого действия».

Класс ApiCall — единственный путь клиента к данным. Метод select формирует вызов функции api с именованными параметрами, проверяя, что имена функции и параметров состоят только из строчных латинских букв, цифр и знака подчёркивания, и передаёт значения через bindValue (рисунок [@fig:apicall]). Методы selectView и selectViewRow читают страницу представления и одну строку представления по коду.

!code[Вызов функции схемы api с именованными параметрами (ApiCall::select)](client/src/db/ApiCall.cpp#method:ApiCall::select){#fig:apicall}

Модель PagedTableModel загружает страницу списка: к параметрам отбора добавляются p_limit и p_offset, общее число строк берётся из колонки total_count первой строки результата, итоговая строка «Итого…» формируется из полей, посчитанных сервером оконными функциями по всему отбору (рисунок [@fig:model-reload]). Код строки (id) в колонки не выводится, а возвращается моделью в роли Qt::UserRole — идентификаторы записей пользователю не показываются.

!code[Загрузка страницы списка (PagedTableModel::reload, начало)](client/src/models/PagedTableModel.cpp#method:PagedTableModel::reload){#fig:model-reload head=30}

Класс AppConfig читает и сохраняет параметры подключения в config.ini, класс RoleConfig по имени группы возвращает набор разделов главного окна и ссылки панели навигации каждого раздела, класс ExcelExport сохраняет табличный документ отчёта в файл .xlsx.

## 3.2 Визуальные компоненты отображения данных

Интерфейс выполнен по макету, согласованному с преподавателем в лабораторной работе № 4. Окно входа «Доступ к информационной базе» содержит поля пользователя и пароля и раскрывающийся блок параметров подключения (рисунок [@fig:login]).

![Окно входа в программу](coursework/pz/img/login.png){#fig:login width=9}

Главное окно (рисунок [@fig:main-window]) состоит из панели разделов слева (набор разделов зависит от группы пользователя), панели навигации раздела, вкладок открытых форм и строки состояния. Начальная страница показывает сведения о пользователе и подключении, описание роли и блок «Текущие дела» — счётчики, открывающие соответствующий список или отчёт.

![Главное окно программы (оператор, начальная страница)](coursework/pz/img/op_home.png){#fig:main-window}

Общие визуальные компоненты:

- DataGrid — таблица (QTableView) с моделью PagedTableModel и панелью страниц; выделяет первую строку после загрузки, сообщает о выборе строки и двойном щелчке, показывает ошибки сервера;
- PagerBar — панель «Показывать по: 20 / 100 / 200, Страница N из M, Записи A–B из N»;
- FormKit — заголовок формы, командная панель с кнопками и полем поиска, подписи, поле с кнопкой выбора «…», сообщения в строке состояния;
- PickerDialog — форма выбора записи (абонента, договора, провайдера) из постраничного списка;
- ReportChart — диаграмма отчёта на основе Qt Charts: накопительные столбцы, линии или горизонтальные столбцы и легенда в отдельной рамке.

## 3.3 Разработка шаблонов приложений для работы с таблицами базы данных

Для работы с таблицами базы данных разработаны три шаблона страниц.

Шаблон списка: заголовок формы, командная панель, строка параметров отбора, таблица DataGrid, связанная с функцией api, и подсказка. Параметры отбора передаются модели как параметры функции, после изменения отбора загружается первая страница. По этому шаблону построены страницы «Договоры», «Сеансы связи», «Провайдеры», «Пользователи», «Общие абоненты», «Договоры без сеансов» и страницы администратора БД. Построение страницы по шаблону показано на рисунке [@fig:list-template].

!code[Страница списка по шаблону (IdleContractsPage)](client/src/ui/pages/ListPages.cpp#method:IdleContractsPage::IdleContractsPage){#fig:list-template}

Составная форма «один-ко-многим» содержит несколько DataGrid, связанных выбором строки: при выборе абонента загружаются его договоры, при выборе договора — сеансы договора с итогами. По этому шаблону построена страница «Абоненты» (подраздел 5.1).

Шаблон отчёта: строка параметров (период, периодичность, провайдер, тип абонента), табличный документ с итоговой строкой и диаграмма ReportChart, команды «Сохранить в Excel…» и «Печать». Данные отчёта целиком формирует функция api.report_*; клиент только раскладывает строки результата по колонкам и рядам диаграммы. По этому шаблону построены отчёты раздела «Статистика» (подраздел 5.6).
