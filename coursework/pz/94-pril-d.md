## Д.1 Требования к серверу

Сервер базы данных — PostgreSQL 18 (допустима версия 16 и выше) на Windows или Linux, кодировка базы UTF-8. Рекомендуемые параметры сервера приведены в разделе 2 (таблица [@tab:server-config]); для защиты паролей в журнале сервера установите log_parameter_max_length = 0. Нужны программы psql и pgAdmin 4; пароль суперпользователя хранится в файле %APPDATA%\postgresql\pgpass.conf, а не в сценариях.

## Д.2 Развёртывание базы данных

1. Создайте базу и роль-владельца (один раз, суперпользователем из базы postgres):
   psql -U postgres -d postgres -v ON_ERROR_STOP=1 -f db/create_db.sql
2. Создайте объекты и данные (повторный запуск пересоздаёт схемы проекта вместе с данными; группы и учётные записи пользователей сохраняются):
   psql -U postgres -d superbd -v ON_ERROR_STOP=1 -f db/build.sql
3. Проверьте базу автоматическими тестами (в конце выводится «Тесты: пройдено 140 из 140»):
   psql -U postgres -d superbd -v ON_ERROR_STOP=1 -f db/tests/run_all.sql

На Windows шаги 2 и 3 выполняет сценарий db\build_and_test.cmd: полный вывод записывается в db\build_and_test.log, в окне выводятся результаты тестов и итог (рисунок [@fig:tests-run]).

Демонстрационные учётные записи (op_donnet, mgr_donnet, chief_main, adm_main, dba_main) создаются сценарием db/seed/030_demo_users.sql без паролей; пароль задаётся командой \password <логин> в psql.

## Д.3 Учётные записи администраторов

Первого администратора БД создаёт суперпользователь по образцу сценария db/seed/030_demo_users.sql: роль с правом входа, членство в группе grp_dba и строка таблицы «Сотрудник» с ФИО; пароль задаётся командой \password <логин>. В разделе «Администрирование» → «Пользователи» администратор БД создаёт администраторов приложения (с временным паролем на сутки), запрещает и разрешает им вход, сбрасывает пароль; свой пароль меняет командой \password в psql (на сервер передаётся только хеш).

Для изменения структуры базы администратор БД выполняет SET ROLE app_owner.

## Д.4 Работа в программе

Раздел «База данных» содержит формы «Таблицы» и «Подключения»:

- «Таблицы базы данных» (рисунок [@fig:dba-tables]) — назначение, число строк, размер, последняя очистка и сбор статистики каждой таблицы проекта; статистику собирает команда ANALYZE, очистку — VACUUM (право даёт встроенная роль pg_maintain);
- «Подключения к базе» (рисунок [@fig:dba-connections]) — текущие сеансы: пользователь, программа, адрес, начало сеанса, состояние и текущий запрос.

Форма «Журнал изменений» выводит записи журнала за период с отбором по таблице, операции и пользователю и изменённые поля записи «было / стало».

## Д.5 Резервное копирование и восстановление

Администратор БД входит во встроенную роль pg_read_all_data и может выполнять резервное копирование без прав суперпользователя:

   pg_dump -U <логин администратора БД> -h <сервер> -d superbd -Fc -f superbd_<дата>.backup

Копия в формате custom (-Fc) содержит структуру и данные всех схем проекта (около 17 МБ). Восстановление выполняет суперпользователь в пустую базу, созданную сценарием create_db.sql:

   pg_restore -U postgres -d superbd --clean --if-exists superbd_<дата>.backup

Учётные записи пользователей в копию базы не входят: их сохраняет суперпользователь командой pg_dumpall --roles-only.
