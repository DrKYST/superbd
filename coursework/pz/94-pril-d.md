## Д.1 Требования к серверу

Сервер базы данных — PostgreSQL 18 (допустима версия 16 и выше) на Windows или Linux, кодировка базы UTF-8. Рекомендуемые параметры сервера приведены в разделе 2 (таблица [@tab:server-config]); для защиты паролей в журнале сервера установите log_parameter_max_length = 0. На компьютере администратора нужны программы psql и pgAdmin 4. Пароль суперпользователя postgres хранится в файле %APPDATA%\postgresql\pgpass.conf и в сценарии не записывается.

## Д.2 Развёртывание базы данных

1. Создайте базу и роль-владельца (один раз, суперпользователем из базы postgres):
   psql -U postgres -d postgres -v ON_ERROR_STOP=1 -f db/create_db.sql
2. Создайте объекты и данные (повторный запуск пересоздаёт схемы проекта вместе с данными; группы и учётные записи пользователей сохраняются):
   psql -U postgres -d superbd -v ON_ERROR_STOP=1 -f db/build.sql
3. Проверьте базу автоматическими тестами:
   psql -U postgres -d superbd -v ON_ERROR_STOP=1 -f db/tests/run_all.sql
   В конце прогона выводится «Тесты: пройдено 117 из 117»; при ошибке — номера непройденных тестов.

На Windows шаги 2 и 3 выполняет сценарий db\build_and_test.cmd: полный вывод записывается в db\build_and_test.log, в окне выводятся результаты тестов и итог (рисунок [@fig:d-tests]).

![Пересборка базы и прогон тестов](coursework/pz/img/tests_run.png){#fig:d-tests width=10}

Демонстрационные учётные записи (op_donnet, mgr_donnet, chief_main, adm_main, dba_main) создаются сценарием db/seed/030_demo_users.sql без паролей; пароль задаётся командой \password <логин> в psql.

## Д.3 Учётные записи администраторов

Первого администратора БД создаёт суперпользователь по образцу сценария db/seed/030_demo_users.sql: роль с правом входа, членство в группе grp_dba и строка таблицы «Сотрудник» с ФИО; пароль задаётся командой \password <логин>. Администратор БД входит в программу своим логином и в разделе «Администрирование» → «Пользователи» создаёт администраторов приложения командой «Создать» (выдаётся временный пароль на сутки), запрещает и разрешает им вход, сбрасывает пароль. Свой пароль администратор БД меняет командой \password в psql: программа такую смену не выполняет, а psql передаёт на сервер только хеш пароля.

Для изменения структуры базы администратор БД переключается на владельца объектов командой SET ROLE app_owner; без неё права владельца не действуют.

## Д.4 Работа в программе

Раздел «База данных» содержит формы «Таблицы» и «Подключения»:

- «Таблицы базы данных» (рисунок [@fig:d-tables]) — для каждой таблицы проекта назначение, оценка числа строк, размер с индексами, последняя очистка и сбор статистики, число последовательных и индексных чтений. Таблицы, по которым статистика не собиралась больше 7 дней, учитываются счётчиком начальной страницы; статистику собирает команда ANALYZE, очистку — VACUUM (право выдаётся встроенной ролью pg_maintain);
- «Подключения к базе» (рисунок [@fig:d-connections]) — текущие сеансы: пользователь, программа, адрес, начало сеанса, состояние и текущий запрос.

## Д.5 Резервное копирование и восстановление

Администратор БД входит во встроенную роль pg_read_all_data и может выполнять резервное копирование без прав суперпользователя:

   pg_dump -U <логин администратора БД> -h <сервер> -d superbd -Fc -f superbd_<дата>.backup

Резервная копия в формате custom (-Fc) содержит структуру и данные всех схем проекта. Копирование от имени администратора БД проверено 28.10.2026: копия рабочей базы — около 17 МБ. Восстановление выполняет суперпользователь в пустую базу, созданную сценарием create_db.sql:

   pg_restore -U postgres -d superbd --clean --if-exists superbd_<дата>.backup

Группы и учётные записи пользователей — объекты кластера и в копию базы не входят; их список сохраняется командой pg_dumpall --roles-only суперпользователем.
