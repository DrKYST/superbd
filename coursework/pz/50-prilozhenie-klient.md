# 5 Разработка клиентского приложения

<!-- Источники: client/src (RoleConfig, MainWindow, страницы), docs/ui/ui-spec.md, docs/ui/deviations.md. Снимки — coursework/pz/img (client/build-dev/claude_pz_shots.cmd). -->

Одна программа обслуживает все роли. После входа сервер сообщает группу пользователя функцией api.whoami, и главное окно строит панель разделов по группе (таблица [@tab:sections]). Инструменты, которые роли не нужны, не показываются; руководитель и главный аналитик работают с теми же страницами, что и оператор, в режиме только просмотра — отдельных страниц одной тематики для разных ролей нет. Скрытие инструментов на клиенте — удобство; запрет выполняет сервер.

Таблица: Разделы главного окна по группам пользователей {#tab:sections widths=24,76 size=11}

| Группа | Разделы и формы |
|---|---|
| Оператор | Главное; Абоненты и договоры (абоненты, договоры); Сеансы связи (журнал сеансов); Мой провайдер |
| Руководитель | Главное; Абоненты и договоры, Сеансы связи — просмотр; Статистика (выручка, трафик по тарифам, новые договоры, крупнейшие абоненты); Мой провайдер |
| Главный аналитик | Главное; Провайдеры; Абоненты и договоры, Сеансы связи — просмотр; Статистика с отбором по провайдеру |
| Администратор приложения | Главное; Администрирование (пользователи); Справочники (типы собственности, города, типы абонентов, тарифы, общие абоненты); Провайдеры |
| Администратор БД | Главное; Администрирование (пользователи, журнал изменений); База данных (таблицы, подключения) |

Начальная страница у всех ролей содержит сведения о пользователе и подключении, описание возможностей роли и блок «Текущие дела» — счётчики, которые считает функция api.home_todo; щелчок по счётчику открывает соответствующий список или отчёт. Числа счётчиков получены теми же функциями, что и открываемые списки, поэтому счётчик и список не расходятся.

## 5.1 Формы и компоненты для работы в роли «Оператор»

Начальная страница оператора показана на рисунке [@fig:main-window] (подраздел 3.2): счётчики «Договоры без сеансов более 30 дней», «Сеансов зарегистрировано сегодня», «Договоров заключено на этой неделе», «Договоры с наступившей датой расторжения».

Страница «Абоненты» — составная форма «один-ко-многим» (рисунок [@fig:subscribers-form]): верхняя таблица — абоненты с поиском по началу наименования или цифрам телефона и отбором по типу абонента и наличию действующих договоров (запрос 8), средняя — договоры выбранного абонента у своего провайдера (запрос 4), нижняя — сеансы выбранного договора с итогами (запрос 2). Двойной щелчок открывает карточку абонента или договора (рисунки [@fig:q06-res] и [@fig:q07-res]).

![Составная форма «Абоненты»: абонент → договоры → сеансы (оператор)](coursework/pz/img/q02_subscribers.png){#fig:subscribers-form crop=form trim=1 squeeze=1 width=12.5}

Страница «Договоры» выводит договоры, заключённые в периоде, с отбором по абоненту (форма выбора) и признаком «Только действующие» (рисунок [@fig:q04-res]); страница «Сеансы связи» — журнал сеансов за период с отбором по договору, IP-адресу или подсети и тарифу и строкой «Итого за период» (рисунок [@fig:q03-res]). Период задаётся полями дат или меню «…» (сегодня, эта неделя, этот месяц, прошлый месяц, этот год). Страница «Мой провайдер» — карточка своего провайдера и список его сотрудников (рисунок [@fig:q05-res]). Список «Договоры без сеансов» открывается счётчиком начальной страницы (рисунок [@fig:q14-res]).

## 5.4 Формы и компоненты для работы в роли «Администратор приложения»

Администратор приложения ведёт учётные записи операторов, руководителей и главных аналитиков на странице «Пользователи» (рисунок [@fig:q11-res]): слева — группы с числом пользователей (запрос 11), справа — пользователи выбранной группы с логином, ФИО, провайдером, признаком «Вход разрешён» и сроком действия пароля. Команды страницы:

- «Создать» — форма «Пользователь (создание)»: логин, ФИО, группа, провайдер (обязателен для оператора и руководителя), признак «Вход разрешён»; после записи сервер возвращает временный пароль, который показывается один раз;
- «Запретить вход» / «Разрешить вход» — функция api.user_set_login;
- «Сбросить пароль…» — подтверждение (рисунок [@fig:reset-confirm]) и окно с временным паролем на сутки; до смены временного пароля пользователю доступна только форма «Смена пароля» (рисунок [@fig:password-change]).

![Подтверждение сброса пароля](coursework/pz/img/reset_confirm.png){#fig:reset-confirm width=7.5} ![Форма «Смена пароля»](coursework/pz/img/password_change.png){#fig:password-change width=7}

В разделе «Провайдеры» администратор видит всех провайдеров и сотрудников выбранного провайдера (рисунок [@fig:q01-res]); отбор «Без сотрудников» показывает провайдеров, которым ещё не назначены сотрудники (рисунок [@fig:q16-res]). Список «Общие абоненты» раздела «Справочники» выводит абонентов, обслуживаемых несколькими провайдерами, сведения которых меняет только администратор (рисунок [@fig:q13-res]). ## 5.6 Генерация результатов итоговых запросов (диаграммы, экспорт в Excel)

Раздел «Статистика» руководителя и главного аналитика содержит четыре отчёта, построенные по шаблону отчёта (подраздел 3.3): «Выручка по периодам» (запрос 15, у главного аналитика без отбора — доли провайдеров, запрос 22), «Трафик по тарифам» (запрос 9), «Новые договоры по типам абонентов» (запрос 12) и «Крупнейшие абоненты». В строке параметров задаются период, периодичность (месяц, квартал, год), провайдер (у главного аналитика) и тип абонента — обязательное распределение по временным отрезкам выполняет сервер. Отчёт состоит из табличного документа с итоговой строкой и диаграммы с легендой:

- «Выручка по периодам» — накопительные столбцы «плата за подключение» и «оплата трафика» по периодам (рисунок [@fig:q15-res]); у главного аналитика — столбцы по группам провайдеров: крупнейшие и «Прочие» (рисунок [@fig:q22-res]);
- «Новые договоры по типам абонентов» — линии по типам абонентов (рисунок [@fig:q12-res]);
- «Крупнейшие абоненты» — горизонтальные столбцы выручки первых N абонентов за период;
- «Трафик по тарифам» — таблица использования тарифов, включая неиспользованные (рисунок [@fig:q09-res]).

Команда «Сохранить в Excel…» записывает табличный документ отчёта в файл .xlsx средствами библиотеки QXlsx с заголовком отчёта, параметрами, шапкой таблицы и итоговой строкой; команда «Печать» выводит документ и диаграмму на принтер. Все вычисления выполняет сервер: клиент только раскладывает строки результата по колонкам таблицы и рядам диаграммы.
